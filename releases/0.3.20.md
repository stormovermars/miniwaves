No schema change, no migration step.

- BUG-022: `-t SLUG`, `-A` and `-j` work before the command too (`mw -t api list`). An unknown command still exits 1 with the reason on stderr.
- BUG-023: `mw --version` and `mw -V` print what `mw version` prints.
- BUG-024: a test now proves every `--help`/`-h` writes nothing (it did not reproduce on 0.3.19).
- TSK-086: qualified ids `tenant:ID` work as the id in show, note, done, start, ready, block, reopen, edit, accept, reject, judge, ask, answer.
- TSK-087: new `mw check [-t SLUG] [-j]` lists parents in inbox or ready while a child is doing or done.
- TSK-088: `mw show` adds "notes cite N commits, M test runs" to the evidence line when the notes name them.
- TSK-089: timestamps in show and log print as `YYYY-MM-DDTHH:MM+TZ`.
- TSK-090: a write from a folder that maps to several tenants (same path, no folder default) warns on stderr unless `-t` or `MW_TENANT` is given.
- TSK-091: `mw tenant list` prints one line per tenant (`* slug  N items  tags`); `-v` and `-j` are unchanged.
- TSK-092: `--ticket KEY` without a tracker stores the key as plain text (1-40 letters, digits, `# _ . -`).
- Fix: `buildlock.sh` no longer relies on `mkdir` being atomic (coreutils on Ubuntu 26.04 is uutils, whose `mkdir` lets two builds take the lock); the lock owner is decided by a noclobber file `LOCK.own`. A stale-lock takeover also uses a noclobber file.
