No schema change (still 9), no migration step. Every new field is optional; an older mw keeps item fields it does not know and drops the new session and tenant `node` fields when it rewrites the board.

One board can now be worked by several computers (nodes), each with its own sessions.

- `mw node set NAME`, `mw node beat [STATE] [--item ID] [-m TEXT] [--left PCT] [--resets TIME]`: one heartbeat file per node under `.miniwaves/nodes/`, so computers never write the same file. A node with no beat for `node.silent` minutes (user setting, default 120) is silent.
- Routing: `mw edit ID node=NAME|any|-` (and `mw add --node`), `mw tenant node SLUG NAME|any|-`, `mw next --node NAME`, `mw list --node NAME`. A computer with a node name filters `mw next` by it. Rows in progress record the node that started them (`started_on`). `cost=N` is an optional row estimate in thousands of tokens.
- `mw fleet [-t SLUG] [-j] [--changed]`: per node live or silent, in flight, stalled, blocked, waiting on an answer, next ready row, movable and held rows; `--changed` prints `no change` when nothing differs from the last run of the same session. `mw get-prompt fleet-coordinator` prints the loop. `mw block ID --on TENANT:ROW` waits on a row of another tenant (a help row for another node); `mw node beat --left 0 --resets TIME` marks a node out until then. The merge driver also needs the `.gitignore` lines in USAGE.md ("Fleets") so lock files stay out of git.
- `mw merge-file BASE OURS THEIRS [PATH]`: a git merge driver for the board files (rows by id, newest field wins, logs as a union, never loses a row or log entry). Setup lines are in `mw help merge-file` and USAGE.md. mw runs no git command.
- Ids are never handed out twice: every allocator raises the tenant counter to the archive's highest id first (the archive and the tenant file are merged separately by git); a conflicted archive stops `mw add` with a message instead of risking a repeat.
- Timed test on a board of 4 tenants, 300 rows and long logs: `mw fleet --changed` unchanged, full `mw fleet`, `mw node beat` and `mw merge-file` each take well under 100 ms in the suite (limits 2 s, 5 s, 1 s and 2 s).
