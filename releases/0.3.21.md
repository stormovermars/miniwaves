No schema change, no migration step.

- New `mw drive send|recv|resume|status|check`: records a session-to-session drive on both boards (a one-line wire format `mw-drive ID SEQ EVENT [N] [TEXT]`, the open line is `open MEMBER GOAL`; mw sends nothing). Per-sender seq with `dup` and refusal of gaps, one drive per remote session (`busy`), no nesting, resume after reap, idle check with `--at`. TEXT is stored only in notes labelled `[data from MEMBER]`, never in titles. New error code `DRIVE_STATE` (exit 2). Gates are not bypassed (a remote result needs `mw done` first; closes are no-evidence with the judge gate respected), `mw next` skips drive children, `wip.session` ignores the drive story, `recv` reads the line from stdin (quoted heredoc, no shell injection). See USAGE.md "Drive".
