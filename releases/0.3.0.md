Read first: this release needs a migration, and one json output changed.

- **Migrate every board to schema 9.** Run `mw migrate` once per workspace (backup `.miniwaves.json.bak8`; only the index is rewritten, tenant files are not touched). 0.3.0 refuses a schema 8 board until you do, and a 0.2.8 or older mw refuses a schema 9 board instead of dropping its new keys. Upgrade every machine and CI image before migrating the committed board. See MIGRATION.md.
- **`mw review -j` has a new `review` list** (always present, `[]` when empty): the blocked items whose latest block reason starts with "awaiting review", the rule `mw news` uses. They also stay in `blocked`, so scripts that count `blocked` keep working; subtract `review` to count real blocks. Plain `mw review` adds a `review` section when there are any.
- **The news pages changed completely.** md, html and text are now one 70-column gopher-style bulletin drawn from the json model; anything that parsed the old pages must read `mw news --format json` instead.

Schema 9 and jobs

- The index gains `jobs` (coordinated jobs: `mw jobs enable|disable|set|show`), a tenant's `job`, and fanfare `sets` and `use`. Job keys are snake_case (`news_out`, `news_url`, `pane_style`, and the new `news_releases`, `metrics`, `tracker`, `tracker_url`); the 0.2.9-dev dotted keys are read and rewritten, unknown job keys are kept. `jobs set` also accepts the snake_case names.
- Items keep fields mw does not know when they are saved.

News model, releases, bulletin and metrics

- `mw news --job ID --format json` is the version-1 model: `job`, `release`, `now`, `happened`, `next`, `metrics`, `summary`. Every list has a cap and a `more` count; item text is at most 200 characters; the whole model is at most 1 MB (a guard trims rows, tenant rows last). The same board gives the same bytes. md, html and text are drawn from it, so a number is computed once.
- `--release` cuts release N+1 under the board lock into `RELEASE_DIR` (`news_releases`, default `<news.out dir>/releases`): `N.json` (frozen model), `N.md`, `N.html`, `latest`, all written durably and never over an existing file. A release compares with release N-1; an empty one is refused with exit 0 ("nothing new since release N") unless `--force`. Only the happened lists and changed metric rows count as news. A corrupt `N.json` blocks `--release` (the error names it) but not drafts. `news.out` always holds the draft; the news desk tick never releases.
- Metrics: the job key `metrics` names a `metrics.json` the job's own tooling writes (split, progress and value rows, at most 256 KB, 8 sections, 40 rows, finite values up to 1e12, text limits, unique row names). An invalid file shows `metrics file invalid: REASON`; deltas are against the previous release.
- Reads of release, hash, summary and metrics files are regular-file only and size-capped (a FIFO or device cannot hang mw). `-o` and the job paths refuse mw's own board files; a leading UTF-8 BOM in metrics and summary files is ignored.
- Tenants at scale: `now.tenants` (up to 2000 rows with counts and `last_change`, attention order), `--tenant SLUG` for one tenant (json only, not with `--release`). Asks come from every tenant in one run.
- Agile and kanban fields (additive): `counts.draft`, `now.backlog` (ready queue, then drafts), `now.recent_done`, `now.sprint` (the open wave nearest to done, with item states), `happened.moved_to_review` and `moved_to_doing`, and `milestone` on done items.

Tracker tickets (optional, off by default)

- A job may name one tracker (`tracker=jira|linear|youtrack|github|gitlab|azure|shortcut|clickup|asana`, `tracker_url=https://...`); items take a ticket with `mw add --ticket KEY` or `mw edit ID ticket=KEY` (or `--ticket KEY`; empty clears it). mw validates the ticket per kind, stores it canonically and builds the link from a fixed template; it never calls the tracker. The mw id is always in the model.

Event feed

- `mw log --since CURSOR|start` is a resumable feed: the cursor carries a fixed 24-hour window of 8-byte key hashes (old cursors keep working), `--lookback` is gone, and `--since-file PATH` keeps the cursor in a file, written atomically.

Other

- `mw reap` prints `spared ...` when only dispatcher or news-desk sessions are due.
- `mw news --width` is checked for text and ignored (bulletins are 70 columns) and refused for md and html.

## Fanfare

- The finale's Stop dialog shows a picture left of the text: `cover.png`, `cover.jpg` or `cover.icns` from the played pair's folder, else mw's built-in party-popper icon (written once to `<dir>/.mw-fanfare-icon.png`). macOS and zenity 3.90+ only; older zenity and kdialog show none, and Windows shows the information icon.
- Also includes the never-tagged 0.2.8 and 0.2.9 changes; see releases/0.2.8.md and releases/0.2.9.md.
